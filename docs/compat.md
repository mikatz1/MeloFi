# 예전 프로젝트 호환성 (MeloFi Studio)

예전 버전에서 저장한 `.mfproj`를 지금 버전에서 열었을 때 오류 없이 열리고, 저장할 때와 같은 소리(특히 채널 사이 밸런스)가 나도록 하는 규칙과 그 검증 방법입니다.

## 프로젝트 버전

| version | 들어온 커밋 | 내용 |
|---|---|---|
| 1 | `ad191f6` | 첫 Studio. `playlist.tracks`가 숫자, 이펙트·버스·오토메이션 없음 |
| 2 | `cadae31` | Composer 2: 인서트 이펙트, 버스, 오토메이션, 오디오 클립, 샘플·슬라이서·신스 채널. 이후 센드(`b0843c3`), 보컬·VST 채널, 박자표 마커(`3ba8e6e`), 신스 프리셋 28개(`88257ae`), 마스터 페이더 위치(`bddf88d`)는 모두 버전 2 그대로 |
| 3 | 이번 변경 | 소리 수정(`7ba56ef`, `bb98162`)을 기준으로 나눈 버전. 2 이하 프로젝트는 열 때 아래 마이그레이션을 거침 |

- `migrate()`(`renderer/studio/model.js`)가 파일을 열 때, 자동 저장·버전 기록·클라우드에서 불러올 때, 실행 취소 스냅샷까지 모두 거치는 길입니다. 버전이 3보다 낮으면 `upgrade()`(`renderer/studio/compat.js`)가 단계별로 고친 뒤 `version: 3`으로 저장됩니다.
- `version`이 아예 없는 프로젝트는 코드가 방금 만든 것(MIDI 가져오기 등)이라 현재 버전으로 봅니다. 지금까지 저장된 파일에는 버전 1 시절부터 항상 `version`이 들어 있었습니다.
- 업그레이드는 원본 객체를 건드리지 않고(`structuredClone`) 한 번만 적용됩니다. 한 번 열어 저장하면 버전 3이 되어 다시 적용되지 않습니다(테스트: 저장 → 다시 열기가 같은 JSON).
- 한계: 버전 번호가 소리 수정과 함께 올라가지 않았기 때문에, 2026-11-12 00:42(`7ba56ef`) ~ 이번 변경 사이에 고쳐진 빌드로 저장한 버전 2 파일도 "수정 전" 파일로 취급됩니다. 그 사이 사용자 자동 저장본(`studio-versions`)은 모두 `bb98162`(03:22) 이전 것이고, 컴프레서가 들어간 것은 11-10 파일 하나뿐(필터는 없음)이라 실제로 잘못 적용되는 경우는 없습니다.

## 소리가 바뀐 변경과 결정

"밸런스"(채널끼리의 크기 관계, 사용자가 귀로 맞춘 것)가 바뀌는 변경은 예전 값으로 되돌려 주고, 원래 버그였거나 마스터 전체 크기만 바뀌는 변경은 새 동작을 그대로 씁니다.

| 변경 | 커밋 | 예전 프로젝트에 미치는 영향 | 결정 |
|---|---|---|---|
| 컴프레서의 숨은 메이크업 게인 제거 | `7ba56ef` | 브라우저 컴프레서가 스레숄드·비율·니에 따라 늘 더하던 게인(기본값 −18 dB / 4:1 / 6 dB에서 +7.0 dB, −30 dB / 6:1에서 +13.8 dB)이 빠져 그 채널만 그만큼 작아짐 | **마이그레이션**: `makeup += autoMakeup(threshold, ratio, knee)` (0.1 dB 단위, 노브 최대 24 dB에서 자름). 메이크업을 움직이는 오토메이션 점도 같은 양만큼 옮김 |
| 필터 레조넌스 의미 | `7ba56ef` | 로우·하이패스의 `res`가 예전엔 Web Audio Q(dB)로 그대로 들어갔고 지금은 Q 비율(0.71 = 평탄). 예전 기본값 0.7(= +0.7 dB)은 지금 −3.1 dB로 들림, 큰 값은 훨씬 날카로워짐 | **마이그레이션**: 로우·하이패스는 `res = 10^(res/20)` (예: 6 → 2.0, 9 → 2.82, 0.7 → 1.08), 밴드패스는 예전에도 비율이라 그대로. `res` 오토메이션 점도 같은 식으로 변환 |
| 악기 음량 트림 (`instruments/levels.json`) | `bb98162` | 70개 악기의 기본 음량이 −17.8 dB(리코더) ~ +12.6 dB 바뀌어 예전 믹스의 밸런스가 깨짐 | **마이그레이션**: `악기` 채널에 `legacyGain: { inst, db: −트림 }`을 넣고, 엔진이 그 채널 스트립 입력(인서트 앞)에 곱함. 채널 악기를 바꾸면(`inst`가 달라지면) 적용되지 않음. 트림 표는 `compat.js`의 `LEVEL_TRIMS_V3`에 고정(나중에 다시 재면 새 버전 단계가 필요) |
| 신스 프리셋 `lvl` 트림 | `bb98162` | 저장된 신스 파라미터에 `lvl`이 없어 0 dB = 예전과 같은 크기. 새 파라미터(FM, 드라이브)도 기본값 0이라 소리 같음 | 그대로(변경 불필요). 예전 프리셋 28개 이름은 모두 지금도 있음(테스트로 확인) |
| 마스터 페이더를 인서트 앞으로 | `bddf88d` | 채널 밸런스는 그대로. 마스터에 컴프·리미터가 있으면 페이더가 이제 "들어가는 크기"가 되어 마지막 리미터의 상한이 최종 피크가 됨 | 그대로. 원래 의도한 수정이고(리미터 뒤에서 페이더가 다시 줄이던 게 문제), 바뀌는 것은 전체 크기뿐 |
| 리미터를 트루 피크 맥시마이저로 | `7ba56ef` | 예전 리미터(20:1 컴프, 상한 −1 dB, 숨은 메이크업)는 상한을 넘었음(상한 −0.3에서 TP +0.1 dBTP). 지금은 상한을 지키고 조금 덜 큼 | 그대로. 상한을 넘던 것이 버그였음 |
| EQ 저역 컷, 딜레이·디스토션 톤의 Q | `7ba56ef` | 컷오프 근처에서만 0.5~0.7 dB 솟던 것이 평탄(Butterworth)해짐. 조절 노브가 없는 고정값 | 그대로 |
| 마스터 디에서 | `7ba56ef` | 예전엔 숨은 메이크업 때문에 6.5 kHz 위를 줄이는 대신 13 dB 가까이 늘 키웠음(`bddf88d`~`7ba56ef` 하루 동안만 있던 버그) | 그대로. 되살리면 안 되는 버그 |
| 마스터 멀티밴드 컴프 | `7ba56ef` | 숨은 메이크업을 근사식으로 빼던 것을 정확히 빼게 됨: 밴드마다 약 0.9~1.1 dB 커짐(마스터 전체) | 그대로. 마스터 전체 크기만 바뀌고, 그 기간에 저장된 파일인지 구별할 수 없음 |

그 밖에 버전 1 → 2(`playlist.tracks` 숫자 → 트랙 배열, 빠진 필드 채우기)는 예전부터 `migrate()`가 하던 그대로입니다.

### 함께 고친 것

- VST 채널의 플러그인이나 VST 호스트가 없는 컴퓨터에서 예전 프로젝트를 내보내면 `VST 렌더 실패: no_host`로 내보내기 전체가 실패했습니다. 이제 그 채널만 소리 없이 두고(`engine.finalize()` → `renderMix().warnings`), 내보내기 알림에 "소리 없이 내보낸 채널: …"을 붙입니다.

## 검증 (tools/e2e)

- `tools/e2e/make-compat-fixtures.mjs`: 각 시대의 `renderer/`를 `git archive`로 꺼내 그 시대의 템플릿·`newProject()`를 node에서 그대로 실행해 `.mfproj`를 만듭니다(그 버전이 저장했을 바로 그 파일). 필요한 것은 그 시대 UI가 했을 방식으로 덧붙입니다(센드, 프리셋, 이펙트, 오토메이션, 샘플·슬라이서·오디오·보컬·VST 채널, 스템 변환 모양). 쓰는 오디오도 여기서 만들어 `fixtures/media/<sha1 20자리>.wav`에 둡니다.
- `tools/e2e/compat-e2e.js` (실행: `node tools/e2e/compat-run.mjs [--private] [--only 이름]`): 임시 userData를 만들어 픽스처를 넣고 앱을 화면 없이 띄워, 픽스처마다
  1. 앱이 파일을 여는 길(`setProject` → `migrate`)로 열고 오류가 없는지, 채널·패턴·노트 수·클립·오토메이션·버스·센드·미디어·박자표·템포·마커가 하나도 빠지지 않았는지, 신스 프리셋 이름·이펙트 종류·악기가 모두 있는지
  2. 피아노 롤·플레이리스트·믹서·라이브 탭을 열고 0.4초 재생, 저장 → 다시 열기가 같은 JSON인지
  3. 오프라인 렌더(`renderMix`, 긴 곡은 앞 12마디): 무음 아님(연주할 것이 있으면), NaN 없음, 샘플 피크 0 dBFS 이하, 렌더 실패 채널은 VST뿐
  
  그리고 업그레이드가 예전 소리를 되살리는지 직접 비교합니다: 예전 컴프레서(브라우저 컴프레서 + 메이크업)·예전 필터(Q dB)·예전 리미터를 Web Audio 노드로 다시 만들어 같은 신호를 통과시키고, 악기 트림은 채널별로 따로 렌더해 보정량을 잽니다. 마스터 순서는 "페이더 1로 렌더 후 페이더 값 곱하기"로 예전 순서를 재현해 비교합니다.
- `--private`는 사용자의 자동 저장본(`%APPDATA%\MeloFi\studio-versions`, `studio-autosave.mfproj`)을 `tools/e2e/fixtures/private/`(git 제외)에 복사해 함께 돌립니다. 원본과 `studio-media`는 읽기만 하고, 오디오·내려받은 악기는 임시 userData에 복사해서 씁니다.

### 남은 것

- 메이크업 마이그레이션은 저장된 스레숄드·비율·니 기준입니다. 이 셋을 오토메이션으로 움직이던 프로젝트는 움직이는 동안 예전 숨은 메이크업과 조금 다를 수 있습니다(지금은 그 값에 맞춰 보정량을 빼므로 크기는 일정해짐).
- 필터 종류(로우·하이 ↔ 밴드패스)를 오토메이션으로 바꾸던 프로젝트는 처음 종류 기준으로만 레조넌스를 변환합니다.
- 채널의 `legacyGain`은 화면에 보이지 않습니다. 예전 프로젝트에 같은 악기 채널을 새로 넣으면 새 기준 크기로 들립니다.
- Studio의 오디오 디코딩 캐시(`media.js`)는 프로젝트를 바꿔도 비워지지 않아, 긴 스템 프로젝트를 여러 개 연달아 열면 렌더러 메모리가 바닥날 수 있습니다(이 테스트에서 발견, 이번 작업 범위 밖).
